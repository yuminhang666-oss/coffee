# 架构与数据

## 范围与入口

独立 Flutter Android 离线应用，applicationId 保持 `cn.coffeejournal.coffee_journal`。首页始终是豆仓，其余标签为手记、回味。只在冲煮后填写，没有实时计时。

- `lib/core/models.dart`：Bean、Cup、StockAdjustment、CoffeeData，schema 1 → 2 显式迁移、完整字段校验、整数库存、示例数据。
- `lib/core/controller.dart`：状态和串行队列。保存、媒体选择、备份准备、恢复、撤销均由 controller 协调。大快照校验在 isolate 完成，小快照避免无必要的线程切换。
- `lib/ui/design.dart`：奶油/浓咖主题、触控与路由、原创占位图、BeanPhoto 和缩放大图。
- `lib/ui/app.dart`：豆仓、档案、手记、回味、设置与恢复确认。
- `lib/ui/editors.dart`：豆子、冲煮记录、校正表单；参数复用、日期重置和返回防丢失。
- Android `MainActivity.kt`：系统文件选择器和单线程桥接。
- Android `CoffeeFiles.kt`：私有照片、后台解码/压缩、AtomicFile、限量 ZIP 导入/导出。页面没有直接写文件的路径。

## schema 2 与整数库存

持久化字段 `Bean.weightTenths`、`Cup.gramsTenths`、校正 `before`/`after` 均为十分之一克整数。模型为表单保留克数显示接口，计算只使用整数；存入前拒绝超过一位小数的重量。购入量 0.1–50000 g，粉量模型保留旧版允许的 0 g，新增表单要求大于 0；单杯最大 1000 g。注水是整数 g，总时长是整数秒。价格始终为整数分。水温选填 1–100 °C，研磨刻度是最多 80 字符的原文字符串，不作跨磨豆机比较。

每条校正独立记录 ID、豆子 ID/名称、时间、当时计算余量、实际余量和原因。校正量固定为 `after - before`，有效余量为：

```
购入十分之一克 - 所有关联手记粉量之和 + 所有库存校正量之和
```

这是一份可追溯的库存流水。编辑过去的手记会重新计算最终余量，也会保留当时校正的前后值。页面在有校正的豆子进行历史编辑或删除前展示计算结果；如果结果小于 0 或超过购入量，拒绝整个操作并提示先校正余量或核对用量。不会截断余量、丢弃校正或自动修改购入重量。校正本身不增加杯数，不改变购豆价格。

编辑相同 ID 替换旧手记；更换豆子返还原豆子库存并扣减新豆子；删除手记返还粉量。移除豆子保留手记和校正，解除关联；校正保留当时豆子名称。一袋一个批次，再次购买新增一袋。已喝完按最终有效余量为 0 判断。

复用只从同一豆子最近日期的手记取粉量、注水、秒数、方式、水温、器具、磨豆机和刻度。新 ID、当前日期；感受、评分、风味、收藏、地点和额外支出留空。复用对象只是表单初值，确认保存后才入库。

## 存档、迁移与失败

沿用原私有文件名 `files/coffee-v1.json`，内容升级为 schema 2。先完整解析 schema 1，保留 IDs、关联、名称、金额、日期、感受、收藏、主题、引导和示例标记；仅将重量转换为整数十分之一克，新照片/水温/器具/磨度留空。首次写入 schema 2 前，AtomicFile 保存 `coffee-schema1-original.json`；后续不覆盖这份原始存档。备份失败就不迁移。读入或迁移失败会锁定编辑并提示重试，原文件保留，不用空数据覆盖。

Dart 队列依次读取最新成功状态，构造候选、完整校验、校验照片存在，再调用 Android AtomicFile，成功才更新 UI。恢复失败不更换当前 JSON 或删除照片。大文件与图像操作均在 Android 单线程执行器，数据导入解析在 Dart isolate。没有 SDK 之外的新运行时依赖。

## 照片

系统 `ACTION_OPEN_DOCUMENT`、`image/*`，不申请相册或磁盘读取权限，不取持续 URI 权限。选中时读取复制，支持最大 30 MB / 8000 万像素；Android 28+ ImageDecoder 处理 EXIF，24–27 的 BitmapFactory + 系统 ExifInterface 保留兼容路径。后台缩至最长边 1600 px，JPEG 最高 84%（必要时继续压缩，保证单文件不超过 2 MB）；另存最长边 360 px 的 JPEG 78% 缩略图，去掉原图元数据。列表只加载缩略图，详情/大图才使用受限原图。

`files/photos/<UUID>.jpg` 与 `thumb-<UUID>.jpg` 是不可变私有文件。更换生成新名称，移除仅清空当前引用。0.2.0 不做垃圾回收，当前、恢复前副本、迁移副本引用过的媒体均不被误删。恢复副本是原 JSON 与被保留的不可变媒体集合，撤销后能恢复照片；不依赖原选择器 URI。取消选图后的孤立媒体可能继续占用本机空间，已在用户文档说明。

## 完整备份与恢复

ZIP manifest `backup.json`：`app=coffee-journal-backup`、`version=2`、唯一照片数；另有 schema 2 `data.json`、`photos/<UUID>.jpg`、`photos/thumb-<UUID>.jpg`。仅打包当前引用照片。仍接受无照片的 schema 1 JSON，并通过显式迁移恢复。

限制：压缩文件和解压总量均最大 64 MB；最多 4002 个文件；JSON 5 MB；manifest 4096 B；每张 JPEG 2 MB；最多 2000 豆子、10000 手记、10000 校正。导出预留 1 MB ZIP 元数据空间，达到上限时提示，不输出不可恢复的大备份。

导入先复制到私有缓存并限量读取，拒绝绝对路径、目录、`..`、反斜杠、未知名称、重复条目、缺图、多余图片、损坏 JPEG、无效尺寸、同名不同内容与未知版本。只把校验过的平面名称放入暂存目录，不照 ZIP 路径解压。媒体按不可变名称添加，绝不覆盖同名异内容文件。随后 Dart 校验所有数据类型、ID、关联、日期、金额、整数库存与主题。此时仍未替换当前存档；用户看到豆子、手记、照片数量并确认后才提交 AtomicFile。

恢复前保留 `coffee-before-restore.json` 及其媒体集合；设置中的“撤销上次恢复”重新校验这份快照和照片后通过同一队列恢复。该快照保留到下一次恢复，不实现多级撤销。即使取消或导入失败，当前存档及照片继续可用；暂存产生但未被引用的不可变图片可能留存。Android 自动云备份关闭，release 不申请 INTERNET。
