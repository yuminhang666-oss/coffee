# 架构与数据

## 边界

独立 Flutter Android 应用，applicationId 为 `cn.coffeejournal.coffee_journal`。入口是豆仓，其他标签为手记和回味。只在冲煮之后填写参数，没有计时器。

- `lib/core/models.dart`：Bean、Cup、CoffeeData，schema 1 JSON 校验、示例数据、余量计算。
- `lib/core/controller.dart`：状态、存储接口、串行写入队列。页面只通过 controller 修改数据。
- `lib/ui/design.dart`：颜色、排版、触控组件、滚动与路由、原创绘制的咖啡杯/豆子图案。
- `lib/ui/app.dart`：豆仓、豆子档案、手记详情、回味、设置与引导。
- `lib/ui/editors.dart`：豆子和冲煮后记录表单，范围与库存校验。
- Android `MainActivity.kt`：单线程原子文件写入、限量读取、系统文件选择器。

## 数据规则

购入重量为 1–50000 g 整数。单杯粉量支持 0.1 g，库存先转为十分之一克的整数累加，再换算显示，避免浮点累计误差。注水量为整数 g，总时长为整数秒。粉水比是注水量 / 粉量，不是萃取产液量。价格以整数分保存；未填价格按 0 统计，不代表实际免费。

余量由购入重量减去关联手记粉量计算，不单独存一份易失配的余量。更新手记会替换相同 ID；修改关联豆子返还原豆子库存并扣减新豆子；删除手记返还库存。移除豆子保留手记里的名称与感受，只清空关联 ID。一次购入是一条独立豆仓记录；同款再次购买请新增一袋，首版不做批次合并。

本月购豆统计以购入日期归月；日期未填写的豆子仅计入“全部时光”。单杯额外支出独立记录，不再计入已填的购豆价格，避免重复计费。杯数是记录数，不能当作完整的实际饮用频率。

## 持久化与失败

本机存档为应用私有目录 `files/coffee-v1.json`。Dart 队列依次取得最新成功状态、执行变更、校验完整快照、调用 Android AtomicFile，成功后才更新界面；写入失败保留旧状态并提示重试。读入失败锁定编辑，不用空白状态覆盖旧数据。

导出和导入都由用户主动调用系统选择器，无全盘或全相册读取权限。导入限制 5 MB，并验证 app/schema、字段类型、日期、ID 唯一性、豆子引用与库存关系。校验通过后仍需确认替换。替换前通过 AtomicFile 保存 `coffee-before-restore.json`；没有将这份内部副本实现成用户可点选的撤销入口，用户应保留自己导出的备份。恢复副本失败时不继续覆盖当前数据。

Android 自动云备份关闭。release 不申请 INTERNET。备份是未加密 JSON，分享或保存时请自行选择目标。后续升级 schema 必须保留旧版本样本并实现显式迁移，不能直接抛弃既有豆仓。

## 发布

0.1.0 使用 Flutter 的默认 debug 签名来签署 release 模式体验包，没有读取或复制记账项目的签名材料。正式发布需另行确定生产签名和后续升级策略。源码与模拟器合成证据入库；APK 放 GitHub Release，不上传缓存、密钥、local.properties、真实用户备份和临时日志。
